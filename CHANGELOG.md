Test: `main-first.test.sh` 57/57 (heavy and light assertions).
- BRAND-IG-1 (`packages/foundation/src/brand.ts`): the Ebda Instagram is `https://www.instagram.com/ebdaai.studio/` (Meta closed `ebdaaistudio`; `ebdaai_studio` with an underscore is a third party and must appear nowhere). Facebook and TikTok keep the `ebdaaistudio` handle. Consumers pick it up on the next foundation tag + `sync`.
- HELD-RERUN-1 (`os/ops/main-first.sh`, `os/ops/tests/main-first.test.sh`): cancelled non-batch runs were held "drain batch goes first" for as long as the drain kept the batch file fresh (hours: 64 runs of 39 PRs sat held while runners were idle, measured 2026-11-18). The hold now applies only while the repo has a queued run younger than `MAIN_FIRST_IDLE_RECENT_S` (6 h; older queued runs are ghosts); with the repo idle the held runs start, batch PRs first then approved first, `MAIN_FIRST_RERUN_CAP` per tick. An API error reading the queue keeps the hold. 4 tests incl. the measured case and two mutants killed. LAUNCH LIST (HELD-RERUN-1b): `$STATE/launch-list-<owner>__<repo>` (one PR number per line, priority order; override `MAIN_FIRST_LAUNCH_FILE`): when idle, launch-list PRs are re-run first in list order and non-launch held runs wait while a launch-list PR still has a run pending in the ledger or queued; a missing/empty/unparseable list keeps the old order, never a hold; the per-tick cap applies.
- MERGE-QUEUE-1 (`ops/drain.sh`, `os/tests/drain.test.sh`): the drain's main gate counts a green `merge_group` run as main's green. When the push-run verdict is pending / unverified / full, it compares main's newest commit's git TREE id with the tree of each completed `merge_group` run of the CI workflow and accepts the main commit when a matching run succeeded AND its `Merge queue gate` job succeeded; it fails closed (API error, no match, a non-success run of the same tree = ambiguity, an in-progress run) and never upgrades a red main. 12 new tests (drain.test.sh 87/87).
- MAIN-RED-FREEZE-1 review fixes: only a 409 is recorded as a ghost (any other cancel failure is retried next cycle); a thaw drops the frozen runs of closed PRs and PRs whose head moved (never re-runs them).
- MAIN-RED-FREEZE-1 (`ops/drain.sh --freeze`, `--thaw-top N`): while main CI is red the drain cancels every QUEUED run that is not on main and not a fixes-main PR head (they compete for the runners main's fix needs), records them in `<name>.frozen` (a cancel the API refuses, a 409 ghost, is remembered and never retried), and when main is green re-runs the oldest N PRs' runs (default 10, AI review first, one batch per cycle). Off by default; never acts while main is pending or unreadable. Tests in `tests/drain.test.sh` (57).
- MAIN-LEASE-1 review fixes + light pool: release needs main's run to complete or 2 consecutive no-queued-job steps (no churn across `needs:` waves); every release re-run is confirmed and a run still cancelling or whose re-run did not take is retried each step (5 steps, then LEASE-RERUN-FAILED) instead of dropped; a run re-run under a main run is never cancelled again for that main run; a queued main job on `ebda-mac` OR `ebda-mac-light` takes the lease and PR runs queued on either pool are cancelled (`MAIN_FIRST_LEASE_LABELS`).
- MAIN-LEASE-1 (`ops/main-first.sh`): while a repo's newest main CI run has a QUEUED job (older than `MAIN_FIRST_LEASE_MIN_QUEUED_S`, 30) main holds a lease: after the normal pass a 30 s loop (`MAIN_FIRST_LEASE_TICK`, at most `MAIN_FIRST_LEASE_BUDGET` 270 s, inside the 5-minute launchd interval) cancels every newly queued non-protected PR run on arrival (every job still queued, heavy label; protected = drain batch PRs, fixes-main PRs, allow-listed branches, runs already started) into a lease ledger, and the moment main has no queued job left it releases the lease and re-runs them (cap `MAIN_FIRST_LEASE_RERUN_CAP` 10, through the phase-3 checks; runs held by a fresh drain batch move to the normal ledger). Never held without a queued main job. `MAIN_FIRST_LEASE=0` turns it off. Tests in `ops/tests/main-first.test.sh` (48).
- OS-TIMEOUT-1 (`.github/workflows/ci.yml`, `os/ops/run-tests.sh`, `os/tests/run-all.sh`): the `OS layer` job's backstop is 45 min (was 25: it ran 25:19 twice on #105 on a loaded Mac runner, all of it inside the one suites step, no lock or queue involved, and GitHub reports a timeout as `cancelled`); a suite or section over `RUN_TESTS_SLOW_S` (default 20 s) prints a `slow` line as it finishes, even with `--quiet`, plus a slowest-5 summary; a `cancelled()` step prints "CANCELLED after N min ... TIMEOUT, not a test failure". Test: `ops/tests/run-tests-slow.test.sh`.
- AUDIT-SPLIT-1 (`.github/workflows/ci.yml`, `.github/scripts/audit-*.mjs`, `.github/audit-allow.json`): the dependency audits (root, brain, hands) block on PRODUCTION dependencies only (`npm audit --omit=dev`, 0 today) and report development advisories in a non-blocking step; GHSA-fc5q-39xc-vjpf (picomatch ReDoS, no patched version, test tooling only) is allow-listed until 2026-12-17; an expired or malformed allow-list entry fails the gate. Measured 2026-11-17: root full audit 5 high, brain 6, hands 5, all that one advisory; production 0 everywhere. Test `test/audit-allow.test.ts`.
- MONEY-SHA-1 + review fixes (`ops/drain.sh`, `ops/lib/drain_eligible.py`): the money gate now requires the commit status `controller/money-review` = success on the EXACT head sha (replaces the label-vs-commit-date check, which failed OPEN on an API error and trusted a client-set committer date); any fetch error, empty or non-list answer refuses. The starve pass is keyed by run id with a cap of 2 requeues and `--starve-min` spacing (it looped forever because createdAt does not move on a re-run). Main is re-read before EVERY gate call. A drain that cannot read its `--main-workflow` raises an ALERT line and a P1 finding `drain-main-unreadable` after 3 cycles. `rerun_verified` never confirms on a failed first read.
- MONEY-SHA-1b: the `controller/money-review` status must be created by an account in `MONEY_STATUS_CREATORS` (default `voidengineer-911`); filtered by creator first, then newest wins; an empty allow-list refuses (a PR's own workflow could post the status as github-actions[bot]).
- RERUN-VERIFIED-1 (`ops/drain.sh`): every re-run the drain asks for (main run cancelled on the newest commit, cancelled-run heal, starved fixes-main run) is read back and must be queued / in progress / on a higher attempt, waiting for a still-cancelling run to finish first, 3 tries; the once-per-run marker is written only after a confirmed re-run, an unconfirmed one is retried on later cycles (max 3) then reported once as RERUN-FAILED. The starve pass skips PRs labelled `hold`. Before this a cancel whose re-run did not take left #811's CI and a main run cancelled for good.
- G47/G49/G74 + DRAIN-STARVE-1 (`ops/drain.sh`, `ops/lib/drain_eligible.py`): the drain now (1) re-runs a cancelled/timed-out run of any workflow on an otherwise-eligible PR (once per run id+attempt, only while main is green with batch room and nothing pending on main, at most the batch room per cycle), (2) needs `money-review-passed` applied after the PR's last non-merge commit, (3) merges nothing unless the newest main run is a success, no main run is pending, and at most `--max-ahead` (3) merges sit on the last green main; unreadable main CI fails closed, a cancelled main tip is re-run once, a `fixes-main` PR may merge alone while main is red, (4) cancels and re-queues a run queued longer than `--starve-min` (20) on a `fixes-main` PR head. New flags `--main-workflow`, `--max-ahead`, `--starve-min`. Tests in `tests/drain.test.sh` (47).
- G39/G40 (loop-watchdog races): `alert-wait not running` waits `ALERT_WAIT_GRACE` s (default 15) and re-checks before reporting; the ack matches by reason SUBSET (a cleared reason no longer re-wakes); the last merge is the MAX `mergedAt` of 50 merged PRs (`gh pr list` orders by creation time, so `--limit 1` gave a stale merge: store said 272 min right after #805 merged). Tests in `tests/loop-watchdog.test.sh`.
- G16 (cross-repo runner fairness): `main-first.sh` now, when a repo's main CI starves, also cancels the OTHER repos' fully-queued heavy-label PR runs round-robin by repo (`MAIN_FIRST_FAIR_CAP` 3 per repo, `MAIN_FIRST_FAIR_TOTAL` 6 per tick), records them in their own repo's ledger for re-request, and rotates the repo order every tick (`rr-cursor`). Main-before-PR is still rule one. Test `tests/main-first-fairness.test.sh`.
- G15 (stall alert counts drain-eligible PRs): new `ops/lib/drain_eligible.py` is the single eligibility rule for `drain.sh` and `loop-watchdog.sh`; the watchdog no longer counts every `ai-review-passed` PR (ebda-store said 64). The drain now also skips PRs labelled `hold`. Tests in `tests/loop-watchdog.test.sh`.
- G14 (scheduled-job failure opens a fixer): `ops/lib/job-failure.sh` + `os-selftest.sh` `check_last_exit`; a launchd job whose last exit code is non-zero files a deduped (per job per day) `review-finding` issue with the secret-masked log tail. Test `lib/__tests__/job-failure.test.sh`.
- G13 (hygiene squash-merge): `wt_squash_integrated` in `ops/lib/wt-safety.sh`; `wt_merge_verdict` and `worktree-cleanup.sh` treat a squash-merged branch as merged by content (tree equals a main commit, or merged PR mergeCommit identical for every changed file).
