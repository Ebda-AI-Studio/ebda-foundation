Both products vendor this: re-run `ebda-foundation sync` after the tag.

## v0.3.1
- Release: tags the main commit that carries PR 74 (Smart Layer engine), PR 72 (InstaPay core), PR 75 (vendoring fixes) and PR 76 (InstaPay modules pass consumer slop gates). Products vendor THIS tag so `foundation.lock.json` names a real main commit (the v0.3.0 tag predates PRs 75 and 76).
- INSTAPAY-SLOP (consumer slop gates): the InstaPay modules pass a consumer's no-any / unused-export guard when vendored. `duplicateIndexContract`'s `Expect` takes `unknown` instead of `any`; internal-only names are no longer exported (`DigestButton`, `DigestPage`, `MAX_DIGEST_ITEMS`, `MAX_FIELD_LENGTH`, `MAX_AMOUNT_MINOR`); the pure helpers a consumer does not import but the tests pin (`formatEgp`, `formatDigest`, `toLatinDigits`, `parseAmountMinor`, `cairoWallTimeToEpoch`, `D1StatementLike`) carry `pq-allow(unused-export)` with the reason. No behaviour change; tests and vectors unchanged. Intended for v0.3.1.
- SMART-LAYER-ENGINE: new module `smart-layer` (export `@ebda/foundation/smart-layer`, plan 4 Phase A engine tasks plus the execution gates of Phases B and C). Input rails (secrets, PII masking moved from Ebda Chat, Egyptian/Franco/English scope + abuse + injection lexicon, untrusted-content fencing), planning rails (tool retrieval capped at 15, per-turn budgets, per-user rate), execution rails (Zod-shaped argument + existence/ownership validation, policy gate with big-change triggers, preview / apply / 24 h undo with etag re-preview, durable single-use confirm approvals bound to the payload hash), output rails (binding claims from typed sources, UI-truth against the capability registry, link/image allowlist, Egyptian register check with one regenerate, "done" claims), the conversation loop (`runTurn`) over an injected Workers AI provider, rollout controls (off / answer-only / suggest / act, per-store flag, product + global + tool kill, shadow), versioned prompt + release id, masked audit rows, help grounding, handoff rules, and the eval harness (pass^k, Cohen's kappa, release gate, registry-derived golden tasks). Model ids are config only (`models.ts`, ruling SL-MODEL-0 provisional). Vectors: `smart-layer-secrets`, `-mask`, `-scope`, `-links`; parity cases added. Rulings SL-PKG-1 ... SL-SCOPE-1, SL-MODEL-0. Adapters (Store, Chat) come in a later PR.
- SMART-LAYER-HARDENING (pr 74 independent security review): the effective policy and undo class are the stricter of the tool's declaration and the capability registry (a registry `confirm` can never apply without its approval; tools that declare less are not offered); undo is claimed by compare-and-set before the inverse runs and the inverse passes the registry + policy gate; link allowlist uses a fixed Ebda host list instead of `*.ebda.app`; oversized input is counted by the rate limiter and never stored beyond 4,000 chars; `runSmartLayerStorageContract` and `checkAdapterContract` ship for adapters; `eraseUser` / `purgeBefore` cover every record type; fence folds full-width and invisible characters; billing claims need typed-source facts and more currencies; a failed apply re-issues its approval; stale re-previews keep the untrusted label. `SmartLayerStorage` gained `unmarkUndone`, `loadAudits`, `loadDecisions`; `PreviewRecord.undo`. The secrets-detector fake credentials are stored split (no gitleaks allowlist for them).
- INSTAPAY-AUTO (v0.3.0; main was already at v0.2.0 from the capability registry, so this takes the next version): shared money-path core for InstaPay auto-confirm (plan `ebda-store/docs/superpowers/plans/2026-11-14-instapay-auto-confirm.md`, tasks F1-F6 + B1). New modules `instapay-extract` (typed receipt extract + injection-proof parser, Cairo DST-correct dates, integer piastres), `instapay-decision` (`decideInstapay`: one pure function, every reason reported, all comparisons fail closed), `instapay-state` (lifecycle table, 48 h grace, first-payment cap, clean-payment rule, unused-credit removal), `instapay-dedupe` (platform-global reference + image index: contract, `D1DuplicateIndex`, `MemoryDuplicateIndex`, schema, `duplicateIndexContract()`), `instapay-digest` (digest text, `ip:` tap codec, HMAC bridge signature). Vectors `instapay-decision.json` (32) and `instapay-extract.json` (37), run by the managed parity test in every consumer. Brain: `POST /api/instapay/notify` (HMAC per product) and the `ip:<s|c>:<id>` tap that calls the product's signed revert endpoint; new Worker secrets `INSTAPAY_BRIDGE_SECRET_STORE|CHAT`, `INSTAPAY_REVERT_URL_STORE|CHAT`. `os/standard/money.md` criterion 21. Consumers re-run `ebda-foundation sync` after the `v0.2.0` tag. Rulings INSTAPAY-1..8 and INSTAPAY-CLEAN-1. Money-review fixes on the same version: first payment fails closed on unknown, clean payment = in a sent digest and not reverted with no extra waiting window (`isCleanPayment` now takes `digestSentAt`), strict one-number amount parser, ASCII-only handles, duplicate ownership is (product, owner, payment), paged digests (`formatDigestPages`), deeper injection scan, `signBridge`/`verifyBridge` take a direction (`notify` or `revert`).

## v0.2.0
- Capability registry and charter guards (lens 192; plan 2026-11-14-charter-guards-registry-help): modules `capability` (Zod schema, enums, `normalizeApi`, `helpUrl`, guard config), `capability-registry`, `ratchet`, `capability-coverage`, `self-service-routes`, `smart-layer-bypass`, `help-article`. `zod` 4.6.7 is a peer dependency of `@ebda/foundation`.
- Registry rule `policy-free-writes` allows a declared read-only POST through a per-entry `readOnlyPost: { routes, reason }` flag naming the excused routes (for example Chat `templates.sync`); PUT, PATCH, DELETE and unnamed POSTs are never excused. New rules `readonlypost-unknown-route` and `screen-wildcard`; `must-confirm` runs on the normalised route; `normalizeApi` folds `[id]` and `{id}` too; the schema rejects impossible dates and empty `roles`.
- Bypass guard covers `env["AI"]`, destructured `AI`, AI Gateway and other provider hosts, provider SDK imports in every form, wrangler.toml, and no longer skips `test/` or `fixtures/` directories under `src/`.
- Ratchet rejects a new baseline file with ids after adoption and a baseline without `ids`; the workflow job passes with a notice on the adoption PR. Seed fails on duplicate or path-unsafe ids. Vendoring products must declare `zod` 4.6.7: `check`, the parity test and the `new` skeleton enforce it.
- CLI: `ebda-foundation capabilities seed | backfill-plan | scaffold` (`lib/capability-seed.mjs`, `lib/capability-backfill.mjs`). Seed against the real 2026-11-14 catalogues: Store 185 and Chat 172 entries, 71 and 23 live merchant entries without a help article.
- CI: `ci/pr-quality/capability-ratchet.mjs` and a `capability-ratchet` job in `pr-quality.yml` (baselines may only shrink, judged against the base branch).
- Standard: `docs/standard/capability-registry.md`.
