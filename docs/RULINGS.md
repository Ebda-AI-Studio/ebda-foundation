Ruling RR-meter - Spend is metered at the forwarder from each API response's real `usage` (input, output, cache reads, cache writes split 5-minute 1.25x / 1-hour 2x, haiku's 100k-token tier, priced per request with pinned model ids) and posted to the brain as it happens (POST /hands/meter, run-token scoped, plus a local ledger), so a job that is killed, times out or is swept still has its spend on record. The forwarder also requires a random per-run key (a local process without it gets 401), refuses any model other than the job's routed one, clamps max_tokens to the ceiling, refuses inference_geo (a 1.1x price tier), and refuses further calls once a job's metered spend reaches its budget (HANDS_JOB_BUDGET_USD, never more than the run has left); `--max-budget-usd` is passed as a second line (the CLI supports it; the forwarder is the cap relied on). Every refusal is an empty-body 401/403/429/503 with `X-Robots-Tag: noindex`; `/health` stays public and carries no data. Why: on 2026-11-09 `https://os.ebda.app/dash/` and its JS/CSS were public (only `/api/*` failed closed) and Access is not set up yet; Ahmad asked for an interim gate as strict as Access. Evidence: `os/cloud/brain/test/dash-auth.test.ts` (unauthenticated /dash/, /dash/dash.js, /dash/dash.css, /api/state -> 401 empty; wrong user/password/malformed -> 401; right credentials -> 200 with CSP + noindex; IP lockout incl. the right password -> 429; Access configured -> Basic ignored, JWT -> 200; nothing configured -> 503). Residuals: Basic Auth sends the password on every request (TLS only, HSTS on) and the browser caches it until it is closed; the global cap means a distributed guesser can lock Ahmad out for 15 minutes (a ~250-bit password is not brute-forceable, so the cap exists to bound DO writes, not to protect the secret). Cost if wrong: the dashboard is unreachable for 15 minutes after a lockout, or (if the password leaked) the halt switch and question answers are exposed until the secret is rotated with `wrangler secret put DASH_BASIC_PASSWORD`.

## PR quality guards (2026-11-12)

Ruling PRQ-1 - Slop guards are baseline-ratcheted per violation id, not per count: a count lets a new violation hide behind a fix elsewhere. The baseline refuses additions (`--update` exits 1) and a fixed violation left in the baseline fails the check. `unused-export` and `duplicate-helper` are our own small scanners (regex + brace matching, no dependency) rather than knip: knip needs each repo's full tsconfig/workspace graph and an install, the guard job must run in seconds with plain node. Cost if wrong: the scanners miss dynamic uses (a string-keyed lookup of an export) and false-positive on exports only a test uses; a false positive is silenced inline with `pq-allow(unused-export): <reason>`.

Ruling PRQ-2 - The learning loop is a PR-body checklist, not a new service: a closed `review-finding` needs a checked Test line naming a test in the diff and a checked Foundation line. Cost if wrong: the Foundation line is a pointer, not proof a guard exists; the reviewer reads it.

Ruling PRQ-3 - The guards judge a PR against its BASE branch, not its own copy: the workflow is `pull_request_target`, the scripts, `.pr-quality.json`, baseline and eslint suppressions come from the base tip, and the PR is checked out into `pr/` only to be scanned. A PR baseline may not hold an id the base's lacks, no violation outside the base baseline is allowed, and no `eslint-suppressions.json` may total more per rule than the base's (totals, so a moved file is fine, a new workspace file is not). The adoption PR itself (base has no baseline) falls back to the plain check. Cost if wrong: a PR branched before main fixed a violation can fail until it merges main; `pull_request_target` runs with repo permissions, so no step may execute PR content.

Ruling PRQ-4 - The PR-body check is warn-only until `bodyCheckEnforceFrom` in `.pr-quality.json` (a date), so adopting it does not turn every open PR red; an unset or unreadable date means enforce now. Cost if wrong: for the grace period a PR without the three sections merges; the warning is still printed in the check log.

Ruling PRQ-5 - Fork PRs are checked, never skipped (a skipped check is a free pass): both pr-quality jobs run for forks from the base workflow, the fork head is checked out into `pr/` and only scanned. The scanner never follows a symlink (lstat on every entry, on each scan root, and on the baseline/config/suppression files, whose parse errors never echo content), so a PR cannot make it read a file outside the checkout. Cost if wrong: a fork PR runs two cheap node jobs with the repo's read-only token; the scanner reading attacker-chosen regular files in the checkout is the accepted exposure.
