# SL-STORE-1

Ruling SL-STORE-1 - Store journal, approvals, audit and counters live in each store's own `StoreDO` SQLite, reached through the same repo layer as other store data (`packages/repo/src/do/smart-layer.ts` + `storeRepo(storeId)` in `apps/api/src/lib/repo-factory.ts`). That way they share tenancy, erasure (`erasure-classification.json` `store-do:*`) and backups. Backups need no change: `apps/api/src/cf/store-do/tables.ts` backs up every live table. D1 `ebda-platform` `system_settings` holds only the platform-wide switches (global and product kill, global mode). No cross-store index is needed. Evidence (measured 2026-11-14): `curl https://api.ebda.app/health` → `"postgres":"removed"`, `"platform_db":"ok"`, commit `49e4e0e41` = ebda-store `origin/main`. The controller measured that prod D1 `system_settings` holds every `platform_cutover` marker (access, ai-usage, analytics, audit, billing, inbox, ops, payments, platform). Cost if wrong: a store not yet on its DO would 503 at the assistant route, the same fail-closed behaviour as `lib/store-backend.ts`.
