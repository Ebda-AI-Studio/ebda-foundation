# Ruling INSTAPAY-CAP-2 (Ahmad, 2026-11-23)

**Ruling INSTAPAY-CAP-2 - a free package's first-payment cap is a fixed 500 EGP.** When a plan's monthly price is exactly 0 (`store-included` or any free package), `firstPaymentCapMinor` returns `FREE_PLAN_FIRST_PAYMENT_CAP_MINOR = 50000` piastres instead of 0, so small first InstaPay top-ups auto-confirm and larger ones still go to a person. A null / missing / invalid price (no plan) STAYS 0: no plan = no automatic credit. Everything in INSTAPAY-CAP-1 (cumulative + atomic cap, dual-control threshold, digest and clean-payment rules) is unchanged. Evidence: prod request WA-G6ZL7XRT (10 EGP, `needs_human`, `FIRST_PAYMENT_OVER_CAP`: one month of a 0 EGP plan is 0); tests in `packages/foundation/src/instapay-state.test.ts` (`INSTAPAY-CAP-2`). Cost if wrong: a forged 500 EGP receipt on a free workspace auto-credits up to 500 EGP once; it is still caught by the duplicate index, the digest and the revert.
