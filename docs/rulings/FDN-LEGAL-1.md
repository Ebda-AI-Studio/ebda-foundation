# FDN-LEGAL-1

Ruling FDN-LEGAL-1 - counsel-approved legal text (Ahmad 2026-11-19; Store #966) is MOVED into `legal/` byte for byte, never reworded: `legal/clauses/VAT-0-clause.md` (the single VAT-0 clause, Ruling VAT-0) and `legal/whatsapp/{ar,en}/whatsapp-{terms,privacy,dpa}.md` (the Chat terms, privacy policy and DPA v1.2, identical in Chat `docs/legal` and the Store's `apps/marketing/legal-source`). `sync` vendors `legal/` under the consumer's `<dir>/legal/`, so the consumer lock's sha256 is the pin that replaced Chat's hand-kept `LEGAL_PINS` in `test/guards.test.ts`; the foundation's own `test/legal.test.ts` pins the source files, and `.gitattributes` marks `legal/**` as `-text`. Changing a clause is a new pin there, a new tag and a re-vendor in both products, and it needs counsel again. Chat keeps `docs/legal` as the published source (another team publishes from it) and asserts each file equals its lock-pinned foundation copy; Chat's publishing README is not counsel text and is no longer pinned. Cost if wrong: if a consumer's copy and the foundation drift, the consumer's test fails (never a silent reword); restoring is `sync` from the last tag.
