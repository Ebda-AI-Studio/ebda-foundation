# SL-SCOPE-1

Ruling SL-SCOPE-1 - The action boundary stands as Ahmad approved it: the assistant may do anything the merchant could do in the dashboard. Every non-forbidden capability in the Store (185) and Chat (172) catalogues gets a tool. They ship in this order: A = read tools · B = preview-class wave 1 · C = confirm wave 2 · D = template writer · E = full coverage (everything else that is live). Page-builder actions are owned by the page-builder v2 plan (project 3) on this engine. `planned`/`in-pr` capabilities get their tool in the PR that ships them, enforced by the Phase E coverage guard. The only carve-out is the **secrets rule** (spec §6.9 gap 19): passwords, MFA secrets, passkey ceremonies, card details, provider/model API keys, one-time tokens and OAuth sign-ins are never typed in chat. The tool for those is a `show_me_where` deep link to the product's secure screen, and the non-secret parts of the task are still done. Accounting writes follow Ahmad's accounting decision: the AI proposes each entry and the merchant clicks each one, never bulk auto-post. The full map is in Appendix: capability coverage. Cost if wrong: a capability ships late, never silently missing (the guard fails CI).
