# FDN-BUMP-1

Ruling FDN-BUMP-1 - consumer drift is closed by a bot, not by memory: `.github/workflows/foundation-bump.yml` runs `ops/bump-consumers.mjs` on every `vX.Y.Z` tag push (plus a daily idempotent catch-up and a manual run) and opens ONE `chore/foundation-<tag>` re-vendor PR per consumer (ebda-store, ebda-whatsapp) through `ebda-foundation sync`, using the consumer's own lock for the vendored dir and parity path. It never merges, never force-pushes, never downgrades, skips a consumer already on the tag or with an open PR for it, opens a draft when `check` finds problems, and notes older open `foundation-bump` PRs it supersedes. Primary path = the workflow (the Mac pool is offline and `launchd` needs a powered Mac); `os/ops/ebda-foundation-bump.sh` (launchd, off by default) runs the same script as a fallback. The workflow's `runs-on` stays inside the NO-HOSTED-RUNNERS-1 lint: while the Macs are offline set the repo variable `EBDA_ANY_RUNS_ON` to `["ubuntu-latest"]` on this public repo only (free minutes). Needs the secret `EBDA_FOUNDATION_BUMP_TOKEN` (fine-grained PAT, Ebda-AI-Studio, ebda-store + ebda-whatsapp, contents + pull requests write): `GITHUB_TOKEN` cannot reach other repos and a PR it opens would not start the consumer's CI; a missing secret fails the run red. Evidence: `test/bump-consumers.test.ts` (dry run opens nothing when current, opens one PR when behind, apply path against a bare remote, never `pr merge`); ebda-store pinned v0.3.2 while the foundation was v0.3.4 (measured 2026-11-23). Cost if wrong: a bad bump PR is opened (never merged) and fails the consumer's CI; if the token expires the bot goes red instead of silent, and drift returns until it is renewed.
