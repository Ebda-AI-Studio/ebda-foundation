# FDN-OBSERVE-1

Ruling FDN-OBSERVE-1 - Alerts, Sentry scrubbing and PII masks are one module, `@ebda/foundation/observe`, extracted from the Store (`pii-mask.ts`, `sentry-url-scrub.ts`, `alerts.service.ts`) and Ebda Chat (`observability.ts`); where the two differ the STRICTER behaviour wins, and `vectors/redaction.json` pins it for both products. Decisions: (1) `maskPhones` is Chat's (any 8+ digit run in ASCII, Arabic-Indic or Persian digits, separated by space, hyphen, dot, parenthesis or `\p{Cf}` bidi marks) with NO ISO-date or order-number exemption; the Store's `redactFreeText` keeps its date shield (its reader is a triage agent) but now also hides Arabic-Indic and Persian digit phones, which it missed. (2) `scrubEvent` = Chat's allowlist (drops user, extra, tags, contexts, request body, cookies, query string, non-allowlisted headers) plus the Store's deep query/path-token/header redaction plus phone and e-mail masking on message, transaction, exception and breadcrumb text; span data is dropped. (3) `telegramAlert` is pure transport (token, chat, fetch and a `ThrottleStore` injected; never throws; 5 s abort; plain text); title, scope line, body, fields and context are masked and denied keys (name, phone, wa_id, token, ...) never render, which the Store did not do for body and context. (4) E-mail in stored error text is `[email]` whole (Chat), not `x***@domain` (Store `scrubEmails` stays for UI masking). Evidence: audit row F6 in the 2026-11-23 plans audit; both repos read at main. Cost if wrong: Store Sentry events lose extra/contexts/tags (debugging context) and alert bodies lose unmasked digits; both are one-line options to relax per product, a leaked customer phone cannot be recalled.
