# FDN-OPS-1

Ruling FDN-OPS-1 - the shared ops scripts (`merge-gate.sh` + `merge-gate-required.mjs`, `pre-push-gate.sh`, `deploy-verify.mjs`, `cron-lint.mjs`, `logpush-setup.sh`) live in `ops/` and a consumer vendors them with `sync --ops <dir>` (Store and Chat: `scripts/foundation`); the consumer's own `scripts/ci/*` becomes a thin wrapper that supplies its defaults and calls the vendored script. The Store's merge gate is the live, gating behaviour, so the foundation script was brought UP to it (PR state first on every poll: MERGED exits 0, CLOSED refuses) and the Store's whole `merge-gate.test.ts` case list now runs here too (`test/merge-gate.test.ts`) and, through the wrapper, in the Store. The foundation gate keeps its own `--workflows` / cross-repo refusal (the Store wrapper pins the Store's own workflows dir and repo, so the Store never reaches that path) and its fork-guard-aware required list. `pre-push-gate.sh` keeps the common steps (action pins, gitleaks, prettier); the Store's related-test and scanner steps stay in the Store as `scripts/ci/pre-push-extra.sh`, run last with `BASE` exported, so the order and the failures are unchanged. The action-pin script is required (a missing one fails the gate; only an explicit empty `PRE_PUSH_ACTION_PINS` opts out). Cost if wrong: a re-vendor that regresses the gate is caught by the Store's merge-gate tests (wrapper to vendored script) and by `sync`'s lock check; reverting is re-pointing the wrapper at the old script body (kept in git history), no data is touched. The foundation's own gate (and Chat's, which uses this copy) newly stops polling a PR that was merged or closed by someone else; before, it polled to the deadline.
