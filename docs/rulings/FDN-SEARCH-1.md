# FDN-SEARCH-1

Ruling FDN-SEARCH-1 - Search is one fold (`foldArabic`, `indexTokens`, `searchTokens`, Ruling FDN-TEXT-1 / SEARCH-2: no NFKC, no locale lowercasing so the Postgres twin `ebda_ar_norm` stays identical) and one set of typeahead hooks (`useLiveSearch`, `useListboxNav`, `highlightSegments`, Store originals) in `@ebda/foundation/web/search`. Ebda Chat swaps `normaliseText` for the SEARCH INDEX and QUERY paths and `useTypeahead`/`highlight` for the shared hooks; `normaliseText` stays for non-search matching (opt-out keywords, bot intents) until each caller is reviewed. Chat's `contacts_fts` and `messages_fts` must be rebuilt after the swap (flag-gated, see `docs/standard/arabic-search.md`). Known limit pinned in `vectors/arabic-search.json`: the canonical fold sends ئ to ي and ؤ to و, so `مسئول` does not find `مسؤول` and `حذاء` does not find `حذائي`; changing that means changing the SQL twin, its migration and the Store vectors together. Cost if wrong: a query that matched in Chat before (Unicode-lowercased Latin, NFKC compatibility forms) may stop matching until the re-index runs; the flag keeps the old fold live until then.
