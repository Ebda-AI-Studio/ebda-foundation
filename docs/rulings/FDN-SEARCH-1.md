# FDN-SEARCH-1

Ruling FDN-SEARCH-1 - Search is one fold (`foldArabic`, `indexTokens`, `searchTokens`, Ruling FDN-TEXT-1 / SEARCH-2: no NFKC, no locale lowercasing so the Postgres twin `ebda_ar_norm` stays identical) and one set of typeahead hooks (`useLiveSearch`, `useListboxNav`, `highlightSegments`, Store originals) in `@ebda/foundation/web/search`. Ebda Chat swaps `normaliseText` for the SEARCH INDEX and QUERY paths and `useTypeahead`/`highlight` for the shared hooks; `normaliseText` stays for non-search matching (opt-out keywords, bot intents) until each caller is reviewed. Chat's `contacts_fts` and `messages_fts` must be rebuilt after the swap (flag-gated, see `docs/standard/arabic-search.md`). The fold is amended by F7-HAMZA-2 (a second, hamza fold A beside the unchanged fold B; match under either); every product and the vectors move together in one release. Cost if wrong: Chat's index text roughly doubles for rows with a hamza seat; a query that matched under the old `normaliseText` fold may stop matching until the re-index runs (a Latin letter with a non-ASCII upper case); the flag keeps the old fold live until then.
