# security — Application Security Gates Rubric

tags: [BOTH]
sources: PLAYBOOK §9, CLAUDE.md (Code-quality rules 1 & 2), reference-iceberg-audit.md (Security/Identity: secrets, GDPR, cookies)

## What "solid" looks like
No raw HTML sinks or unparameterized queries reach user input; every API edge validates with Zod/Yup; `npm audit` is 0/0/0/0 at every severity with a CI gate; secrets never live in git and are scanned on every push; PII is masked in logs and CSV exports are formula-escaped; a tracking-consent gate precedes any pixel; erasure/export endpoints exist; CSP + HSTS + nosniff are set in prod.

## Criteria
| # | Criterion | Solid (grade 2) | Gap detection | Severity |
|---|---|---|---|---|
| 1 | No XSS sinks on user input | No `dangerouslySetInnerHTML`/`innerHTML`/`v-html` fed by user data; sanitized if unavoidable | grep src for `dangerouslySetInnerHTML`/`innerHTML\s*=`/`v-html`; flag any reachable from request input | Critical |
| 2 | No injection via raw queries | All DB access via Prisma/parameterized; no string-built SQL with user input | grep for `$queryRawUnsafe`/`$executeRawUnsafe`/template-literal `SELECT .*${` | Critical |
| 3 | Zod/Yup at every API edge | Every route handler parses body/query/params through a schema before use | grep route files for handlers lacking a `.parse(`/`.safeParse(`/validator middleware on the input | High |
| 4 | npm audit 0/0/0/0 + CI gate | Zero vulns at every severity; CI runs `npm audit --audit-level=low` (or no flag), not `--audit-level=critical` | run `npm audit --audit-level=low`; grep `.github/workflows/*` for the audit step + its `--audit-level` value | High |
| 5 | Secret scanning in git | gitleaks runs pre-commit + CI with `.gitleaks.toml` allowlist + `.gitleaksignore`; no secrets committed | file-exists `.gitleaks.toml` + `.gitleaksignore` + a gitleaks workflow; grep `.env`-shaped keys tracked in git | Critical |
| 6 | Log injection / PII masking | User input is not interpolated raw into log lines; PII fields masked before logging | grep `logger.\w+\(.*req\.`/`console.log(.*req\.` passing raw input; confirm a mask helper on PII fields | High |
| 7 | CSV/export formula injection guard | Any cell starting with `= + - @` or a control char is prefixed with `'` inside the serializer | grep export/csv code for a `csvField`/escape helper guarding leading `= + - @`; flag raw `join(',')` of user data | High |
| 8 | Tracking consent gate | No analytics/marketing pixel fires before consent is recorded | grep for pixel/gtag/fbq/posthog init not gated behind a consent check | High |
| 9 | Erasure + export endpoints | `/auth/me/erase` + `/auth/me/export` (or equivalent) exist on any auth system | grep routes for an erase + export endpoint handling the authed user's data | High |
| 10 | CSP + HSTS + nosniff in prod | helmet (or equivalent) sets Content-Security-Policy, Strict-Transport-Security, X-Content-Type-Options in prod | grep for `helmet(`/header config setting `contentSecurityPolicy`/`hsts`/`X-Content-Type-Options`; confirm not disabled in prod | High |
| 11 | Runtime validator in lockstep with shared types | Widening a shared TS union/enum/type (and the UI that produces it) MUST update the API runtime validator (Zod enum + new fields) in the SAME change — TS is compile-time only; the validator is the actual API gate, so a new value 400s and `.strip()`/passthrough schemas silently drop new fields. Applies to DB/Prisma enums too if persisted | when a shared union/enum changes, grep API route schemas for the matching `z.enum(`/field list and confirm it was widened too; symptom = a feature that typechecks + reviews clean but returns 400 on real save | High |
| 11a | **Schema-parity guard for persisted settings objects** (automated enforcement of #11) | Any evolving typed settings object persisted through a `.partial()`/`.strip()` Zod schema (e.g. a page-builder/layout/theme settings PUT) MUST have a unit test asserting **every top-level key of the shared TS type is present in the save-schema's accepted keys** — and a runtime key-list (`const X_TOP_LEVEL_KEYS = [...] as const`) kept in lockstep with the type via compile-time assertions (`keyof T extends typeof KEYS[number]` both directions). Without it, a key added to the type but not the schema is **silently stripped on save** ("saves don't stick" — and the unsaved *preview* still works because preview stores the raw body, masking it). This class recurred 4× in a previous storefront product (productsPage/cartPage/locationsPage/bottomBar) before the guard | for each `.partial()`/`.strip()` schema that persists a shared settings type, confirm a `*-schema-parity` test exists comparing `Object.keys(schema.shape)` ⊇ the type's key list; symptom = merchant reports "page builder doesn't save X" while preview shows it. Pattern: a previous storefront product `tests/unit/layout-schema-parity.test.ts` + `LAYOUT_TOP_LEVEL_KEYS` in `@force/shared` | High |
| 12 | Every merchant-supplied href/URL scheme-validated before render | Any user/merchant-supplied URL rendered as `<a href>` or used for navigation passes a scheme allowlist (http/https/relative) so `javascript:`/`data:` is neutralized — not just hero CTAs but nav menu, footer links, utility bar, floating-widget custom links | grep for `href={` / `window.location` fed by merchant data lacking a `sanitizeUrl`/safe-url/scheme check; confirm the same helper covers ALL link surfaces, not only the first one fixed | High |
| 12a | Merchant-supplied iframe `src` host-allowlisted (exact) | Any user/merchant-supplied URL rendered as an `<iframe src>` (map embeds, video embeds, custom widgets) MUST be parsed with `new URL()` and have its **hostname compared EXACTLY** against an allowlist (never a substring/`includes`/regex-`/maps\/embed/` check), with the path anchored (`^/maps/embed`). A substring check lets `https://evil.com/maps/embed` through → an attacker page framed on the storefront. Prefer routing all non-allowlisted inputs through a hardcoded-host constructor (e.g. `https://www.google.com/maps?q=${encodeURIComponent(q)}&output=embed`). https-only. | grep for `<iframe` whose `src` derives from merchant/user data; confirm a `new URL().hostname === ...` exact allowlist (not `.includes('/maps/embed')`). Iframe-host sibling of #12 (which covers `<a href>` schemes). Pattern: a previous storefront product `mapsEmbedSrc()` in `@force/shared/schemas/location.ts` | High |
| 13 | gitleaks allowlist is commit-independent | CI-only test secrets allowlisted by literal value / `stopwords` in `.gitleaks.toml` (`useDefault=true`), NOT by SHA-pinned `.gitleaksignore` fingerprints (which stop matching after a squash-merge → the same test secret re-fails every PR); cover both encoded + decoded forms | grep `.gitleaksignore` for fingerprint lines used as the only allowlist | Medium |
| 14 | Clickjacking / framing protection on every response | Both `X-Frame-Options: DENY` (or `SAMEORIGIN` where intentional) AND `Content-Security-Policy: frame-ancestors` are set — not just the login page, every response — so the app cannot be embedded in an attacker's iframe and driven with invisible clicks | `grep -rniE "x-frame-options\|frame-ancestors" apps/*/next.config.* apps/*/src/middleware.* apps/*/src/**/headers*.ts 2>/dev/null`; confirm it's set globally (middleware/`next.config` `headers()`), not one route, and that CSP without a `frame-ancestors` directive isn't mistaken for framing protection (`default-src` doesn't cover it) | Critical |
